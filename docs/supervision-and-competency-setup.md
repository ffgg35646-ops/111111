# الغرف المشتركة وملف الكفاءات المهنية

## إعداد الخدمات

أضف المتغيرات التالية إلى بيئة الخادم، ولا تضع الأسرار في ملفات Git أو كود المتصفح:

```env
LIVEKIT_URL=wss://YOUR_PROJECT.livekit.cloud
LIVEKIT_API_KEY=your_livekit_api_key
LIVEKIT_API_SECRET=your_livekit_api_secret
SUPERVISION_TOKEN_SECRET=replace_with_a_random_secret_at_least_32_characters
MONGODB_URI=mongodb+srv://...
MONGODB_DATABASE=clinical_learning
```

- أنشئ مشروعاً في LiveKit Cloud أو جهّز خادم LiveKit ذاتياً، ثم أدخل عنوان WebSocket والمفتاح والسر.
- أضف اتصال MongoDB Atlas واسم قاعدة البيانات. تُنشأ مجموعة `clinical_competency_reports` تلقائياً عند حفظ أول تقرير.
- يجب أن يكون `SUPERVISION_TOKEN_SECRET` قيمة عشوائية قوية بطول 32 حرفاً على الأقل.

## مسار الجلسة

1. ينشئ المشرف غرفة ويُصدر الخادم ثلاثة رموز دخول موقّعة: للمشرف، والمتدرب، ومحرك VR.
2. تسمح الغرفة بحد أقصى ثلاثة اتصالات: مشاركان بشريان وجهاز VR واحد. صلاحية إدارة الغرفة للمشرف فقط، ورمز محرك VR لا يملك صلاحية نشر أو استقبال مسارات الصوت والفيديو؛ قنوات التطبيق ترسل رسائل التوجيه والقياسات إلى هويات المشرف والمتدرب المحددة بدلاً من بثها لجميع المشاركين.
3. رابط دعوة المتدرب يضع الرمز داخل جزء URL بعد `#` حتى لا يُرسل الرمز في طلب HTTP الأول.
4. يستخدم الطرفان WebRTC للصوت والفيديو ومشاركة الشاشة. لا يبدأ الميكروفون أو الكاميرا تلقائياً؛ يفعّلها كل مستخدم من أدوات الغرفة بعد منح الإذن.
5. ينسخ المشرف رمزاً قصير العمر لمحرك VR ويربطه بعميل LiveKit في الجهاز. الرمز مخصص لنشر بيانات الجهاز فقط ولا يتيح نشر أو استقبال مسارات الصوت/الفيديو. ترسل قنوات التطبيق رسائلها إلى هويات المشرف والمتدرب فقط، ولا تستخدم البث العام للرسائل السريرية.
6. قناة `clinical-coaching` تحمل توجيهات المشرف وردود المتدرب بشكل حي.
7. قناة `vr-telemetry` تحمل نتائج المحرك، ويستقبلها المشرف ويضمّنها في التقرير عند الحفظ.
8. قناة `vr-scene-state` تعرض حالة المشهد والخطوة الحالية وموضع المتدرب للمشرف.
9. بعد الجلسة يقيّم المشرف ست كفاءات من 1 إلى 5 ويحفظ التقرير في ملف المتدرب.

## شكل رسائل VR

أرسل JSON عبر LiveKit Data Channel على topic باسم `vr-telemetry`:

```json
{
  "type": "posture_score",
  "label": "استقامة الجذع",
  "value": 4.2,
  "unit": "/5",
  "source": "unreal-openxr",
  "occurredAt": "2026-11-21T16:00:00.000Z"
}
```

أنواع القياسات التي يمكن ربطها تلقائياً بالأدلة المهنية:
- `posture_score` و `gaze_score`: أدلة للغة الجسد والتواصل البصري. صفحة `/posture` ترسل هذين النوعين تلقائياً كل 3 ثوانٍ عند ربطها ببيانات الجهاز المنسوخة من المشرف وتشغيل الكاميرا.
- `clinical_assessment_score`: أدلة لتنفيذ خطوات التقييم السريري.
- `safety_compliance_score`: أدلة الالتزام بالسلامة.
- `interaction_distance_cm`: مسافة تفاعل رقمية، ولا تتحول وحدها إلى درجة كفاءة.
- `procedure_step`: حدث إكمال خطوة إجرائية.

يمكن استخدام الدالتين `publishVrTelemetry` و`publishVrSceneState` من `components/vr-telemetry-bridge.ts` في عميل متصل بالغرفة. الأولى ترسل مؤشرات الأداء، والثانية تزامن اسم المشهد والخطوة الحالية وموضع المتدرب ليظهر التحديث للمشرف لحظياً.
- ينسخ المشرف من واجهة الغرفة JSON اتصال الجهاز، ويحتوي `serverUrl` و`roomName` و`token` و`role`. يحتفظ محرك VR بهذه القيم في ذاكرة آمنة طوال الجلسة ثم يتخلص من الرمز بعد انتهاء صلاحيته.
- ترسل الدوال المساعدة بيانات القياسات وحالة المشهد إلى الهويات البشرية المصرح بها باستخدام `destinationIdentities`، ولا ترسلها إلى جميع المشاركين بشكل افتراضي.
- أضيفت واجهة HTTP لمحرك Unreal/OpenXR في `/api/supervision/vr-telemetry`. تستخدم Bearer token الخاص بجهاز VR، وتتحقق من توقيع LiveKit ودور `vr-device` واسم الغرفة وصلاحية `canPublishData` قبل تخزين الأحداث.
- تسحب واجهة حفظ التقرير القياسات المعلقة الخاصة بالغرفة نفسها وتضمّنها في التقرير ثم تربطها بمعرف التقرير. القياسات غير المرتبطة تنتهي صلاحيتها تلقائياً بعد 30 يوماً.
- مشروع المصدر الأصلي للمحرك في `native-vr/`; تعليمات البناء والربط في `native-vr/README.md`. لا يتضمن مجسماً بشرياً واقعياً أو اتصال صوت Realtime أصلياً داخل Unreal حتى الآن.
- إذا كان محرك Unreal/OpenXR مستقلاً عن تطبيق الويب، يلزم ربط Data Channel عبر SDK مناسب للمحرك أو جسر WebRTC؛ لم تتم إضافة مكوّن Unreal أصلي إلى المستودع بعد.
- مشاركة شاشة تطبيق VR تتم من أحد الطرفين عبر عناصر تحكم LiveKit؛ الرمز المنفصل للجهاز مخصص للبيانات فقط ولا يرسل فيديو المشهد.

## حفظ ملف الكفاءات

تُحفظ التقارير في `clinical_competency_reports` وتضم:
- رمز المتدرب والاسم المعروض وعنوان السيناريو.
- درجات الكفاءات الست ومتوسطها.
- ملاحظات المشرف.
- أحداث وقياسات VR التي وصلت إلى الغرفة قبل حفظ التقرير.
- معرف الغرفة وتاريخ الحفظ ومعرف التقرير.

التقييم النهائي في النسخة الحالية يعتمد درجات المشرف. قياسات VR تُحفظ كأدلة رقمية مرتبطة بالتقرير، ولا تستبدل قرار المشرف أو تُحوّل تلقائياً إلى حكم مهني نهائي. يمكن إضافة قواعد تقييم معتمدة لاحقاً بعد اعتمادها من المؤسسة.

## حدود الأمان والحوكمة الحالية

- هذه المرحلة لا تحتوي بعد على نظام دخول أو SSO للمؤسسة. ملف المشرف الحالي يُنشأ كجلسة موقعة في المتصفح لأغراض النموذج الأولي؛ أي شخص يستطيع إنشاء غرفة جديدة ما لم تُوضع واجهة API خلف تسجيل دخول مؤسسي. لا تعتبر هذه الجلسة بديلاً عن التحقق من هوية المشرف.
- يجب ربط إنشاء الغرف وإصدار التقارير بصلاحيات المستخدمين الفعلية قبل الاستخدام المؤسسي.
- لا تحفظ هذه الواجهة الصوت أو الفيديو ولا تشغّل التسجيل تلقائياً.
- لا ترسل بيانات مرضى حقيقية أو معرفات شخصية إلى القنوات أو الملاحظات في النموذج الحالي.
- احتفظ بالتقارير للغرض التدريبي فقط، مع سياسة موافقة واحتفاظ وتدقيق وصول تحددها المؤسسة.
- رموز الغرف تنتهي بعد ساعتين، ورمز جهاز VR يجب أن يُعامل كسِر ويُزال من إعداد الجهاز بعد الجلسة. تُحذف الغرفة بعد خلوها وفق مهلة LiveKit المحددة عند إنشائها.

## الاختبارات المطلوبة قبل الإنتاج

- تجربة متصفحَين وجهازَين على شبكات مختلفة، مع اختبار إعادة الاتصال وانقطاع أحد المشاركين.
- اختبار أذونات الكاميرا والميكروفون ومشاركة الشاشة على Chrome وSafari والمتصفحات المستهدفة.
- اختبار وصول بيانات VR الفعلية وتوافق قيمها مع معايرة أجهزة المؤسسة.
- مراجعة الصلاحيات وتسجيل الدخول وحماية التقارير واختبار إساءة استخدام روابط الدعوة.
- تشغيل `npm run typecheck` و `npm run lint` و `npm run build` بعد تثبيت الاعتماديات.
