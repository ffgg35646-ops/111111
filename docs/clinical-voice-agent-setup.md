# إعداد وكيل المحادثة الصوتية السريرية

## المتغيرات المطلوبة
أضف إلى بيئة التشغيل (ولا تضع المفاتيح في Git):

```env
AI_GATEWAY_API_KEY=ضع_مفتاح_Vercel_AI_Gateway_هنا
CLINICAL_AI_MODEL=openai/gpt-6-astra
```

يمكن تغيير CLINICAL_AI_MODEL إلى أي معرف نموذج محادثة متاح في AI Gateway. يجب التحقق من توفر النموذج في كتالوج Gateway قبل التشغيل.

## طريقة عمل النسخة الحالية
- المتصفح يلتقط الكلام باستخدام Web Speech API عند توفره، ويتيح الكتابة كبديل.
- النص يرسل إلى مسار Next.js server-side.
- الخادم يستدعي نموذج اللغة عبر AI SDK وVercel AI Gateway، ويبث الرد النصي إلى الواجهة.
- المتصفح ينطق الرد باستخدام SpeechSynthesis بصوت عربي متاح على الجهاز.
- لا يرسل كود المتصفح مفتاح Gateway ولا يحفظ التسجيل الصوتي أو سجل المحادثة في قاعدة بيانات.

## حدود مهمة
هذه نسخة محادثة صوتية turn-based وليست بثاً صوتياً ثنائي الاتجاه منخفض التأخير. التعرف على الكلام والنطق يعتمدان على دعم المتصفح والأصوات المثبتة. لا توجد حالياً مزامنة تلقائية للـ visemes أو WebRTC/Realtime audio. يلزم تنفيذ ذلك لاحقاً وربطه بعارض الشخصية وUnreal/OpenXR.

المستودع لا يحتوي حالياً على مصادقة مستخدمين أو صلاحيات مشرف أو rate limiting أو قاعدة بيانات. لذلك يجب عدم فتح واجهة API للعامة أو استخدامها مع بيانات مرضى حقيقية قبل إضافة المصادقة، تحديد المعدل، إدارة الموافقات، وسياسة الخصوصية والاحتفاظ.

## السلامة السريرية
المحادثة تدريبية وليست تشخيصاً أو علاجاً. ملف السيناريو يحدده المختص، وعلى الوكيل ألا يخترع معلومات أو يكشف معلومات مقيدة قبل السؤال المناسب. يجب اختبار كل سيناريو واعتماده من مختص قبل استخدامه في تدريب رسمي.
