# إعداد وكيل المحادثة الصوتية السريرية

## المتغيرات المطلوبة
أضف إلى بيئة التشغيل ولا تضع المفاتيح في Git:

    AI_GATEWAY_API_KEY=ضع_مفتاح_Vercel_AI_Gateway_هنا
    CLINICAL_AI_MODEL=openai/gpt-6-astra

تحقق من توفر معرف النموذج المحدد في كتالوج AI Gateway قبل التشغيل.

## طريقة العمل داخل قاعة المحاكاة
- صفحة /simulation تحمل الشخصية البشرية ثلاثية الأبعاد داخل مشهد Three.js / React Three Fiber.
- لوحة المحادثة الصوتية لوحة ثلاثية الأبعاد داخل نفس العيادة ويمكن الضغط عليها بمؤشر النظارة أو وحدات التحكم.
- Web Speech API يلتقط دور المتدرب ويحوله إلى نص عند دعم المتصفح، مع إدخال نصي بديل.
- يرسل تطبيق Next.js النص وملف الحالة إلى /api/clinical-agent.
- يستدعي الخادم نموذج اللغة باستخدام AI SDK وVercel AI Gateway ويبث الرد النصي.
- ينطق المتصفح الرد باستخدام SpeechSynthesis بصوت عربي متاح على الجهاز.
- يختار مشهد الشخصية حركة Talk أثناء الكلام، ويحرّك فكها عبر morph target تقريبي.
- لا يرسل المتصفح مفتاح AI Gateway إلى العميل.

## نمط الحوار
التنفيذ الحالي Push-to-talk / turn-based: يتحدث المتدرب في دوره، ثم يكتمل التعرف الصوتي ويُرسل النص إلى الوكيل، ثم يسمع الرد. ليس محادثة صوتية Full-duplex ولا بثاً صوتياً مستمراً منخفض التأخير. يمكن إيقاف صوت الشخصية، وإعادة الحديث، واستخدام النص عند عدم توفر التعرف الصوتي.

## الشخصيات
- يحتوي المشروع على موديلات رجل وامرأة بالغين من أصول Avatar Studio / Microsoft Rocketbox.
- يمكن تحميل ملف GLB بديل من واجهة المحاكاة للجلسة الحالية.
- ملف GLB المخصص لا يُرفع إلى الخادم ولا يُحفظ بشكل دائم في هذه المرحلة.
- الموديلات الافتراضية ليست بزي سعودي تقليدي، ولا توجد حالياً موديلات أطفال أو مراهقين معتمدة. وفّر أصولاً مرخصة ومناسبة للعمر والزي المطلوب قبل اعتماد تلك الشخصيات.
- إشعارات الأصول وتراخيصها موثقة في docs/third-party-avatar-notices.md.

## البيانات والخصوصية
- الصوت الخام لا يُسجّل أو يُحفظ في سجل النشاط.
- عند إنهاء الجلسة تُرسل نصوص أدوار المتدرب والشخصية مع Rubric وأحداث القاعة إلى platform_learning_activities.
- يجب عدم إرسال بيانات تعريفية أو سجلات مرضى حقيقية.
- يجب إضافة المصادقة والصلاحيات وتحديد المعدل وسياسة الاحتفاظ والموافقة قبل فتح الخدمة للاستخدام المؤسسي العام.

## اختبارات الاعتماد
- اختبار WebXR عبر HTTPS على النظارة المستهدفة.
- اختبار منح إذن الميكروفون وسحب الإذن والتعامل مع انقطاع التعرف الصوتي.
- اختبار صوت عربي واضح من الأصوات المتاحة على الجهاز.
- التحقق من أن رد الشخصية يطابق ملف الحالة ولا يخترع معلومات أو يكشف تفاصيل مقيدة.
- اختبار تحميل GLB والحركة وMorph Targets وCORS والأداء على النظارة.
- اختبار عدم حفظ الصوت الخام، والتحقق من سياسة الاحتفاظ بنصوص المحادثة.

## مسار الصوت الحي ثنائي الاتجاه

أضيف مسار Realtime/WebRTC إلى شاشة المحاكاة، ويُنشئ الخادم بيانات عميل مؤقتة قبل أن يتصل المتصفح مباشرة عبر WebRTC. يحتاج هذا المسار إلى:

```env
OPENAI_API_KEY=your_server_side_api_key
CLINICAL_REALTIME_MODEL=gpt-realtime-2.1
```

- لا تُرسل OPENAI_API_KEY إلى المتصفح أو إلى ملف Git. الخادم ينشئ مفتاح عميل مؤقتاً قصير العمر.
- تُفعّل خاصية Server VAD، ويُسمح بمقاطعة رد الشخصية عند بدء المتدرب الكلام.
- تُحفظ النصوص المستخرجة من الحوار فقط عند إنهاء المحاكاة وحفظها؛ لا يخزن هذا المسار التسجيل الصوتي الخام في قاعدة بيانات المنصة.
- يوجد حد طلبات مبدئي في ذاكرة الخادم لتقليل إصدار الرموز المؤقتة المتكرر. يلزم تفعيل Rate Limiting موزع على مستوى Edge/Redis قبل الاستخدام العام.
- يظل مسار AI Gateway النصي/المتناوب متاحاً كبديل عند غياب مفتاح OpenAI أو عدم دعم WebRTC.
- اختبر نموذج Realtime واللغة العربية والأذونات والصوت ثنائي الاتجاه على الأجهزة الفعلية قبل الإطلاق.
